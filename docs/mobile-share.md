# 手机分享存入记忆

需要网站登录态的内容，先在设置 · 网站导入 Cookie，或使用平台真实二维码扫码。服务器保存后，手机分享的该站链接会复用登录态读取。B站已接入官方二维码生成；小红书目前使用 Cookie 导入，真实扫码尚未通过。具体操作见 [网站登录](platform-login.md)。

## Android

1. 用 Chrome 打开服务器的 HTTPS 地址，在设置 · 设备生成配对码，完成手机配对。
2. 在 Chrome 菜单选择安装应用。安装后打开一次，等待网页加载完成，让分享接收 worker 就绪。
3. 在小红书、B 站或其他 App 选择分享，再选择记忆。只有复制链接选项时，先复制完整分享文案，然后通过支持文字分享的 App 分享到记忆。
4. 分享页自动发送，点击原件回执进入工作台查看整理结果。首次未配对时先完成配对，分享内容仍在手机本地。

配对完成后可以直接打开资料库；刷新保留当前页面。配对页只从地址中移除已经读取的配对码，其他页面参数保留。

同一次分享中的多图作为一份原件；小红书链接与截图通过原有链接绑定保留一份，截图可包含评论区。视频文件走原有视频上传处理。多个非图片附件分别产生回执。含 B 站、b23.tv、小红书、xhslink.com 的分享文案会抽取网址，保留网站需要的签名参数。只传链接时，实际可读取内容仍由既有平台解析器和平台访问条件决定。

发送前内容暂存在当前浏览器的 IndexedDB。完成后清除本地正文和附件，只保留回执定位。每条分享可单独清除，其余待发送内容和回执保持；批次中一项发送失败后，其余分享继续发送。切换账号、用户空间或更换配对设备后，已绑定的旧分享不会发送给新身份。关闭页面再打开 `/#capture=pending` 可重试当前身份的队列。网络中断后手动重试保持同一编号，服务端复用已保存原件及回执。服务器在文件落盘与登记编号之间意外退出时会提示上传状态待核对，先到工作台核对，不自动再存一份。

这里实现安装式网页分享接收，要求 HTTPS 和支持 Web Share Target 的浏览器；iPhone 使用下面的快捷指令。当前版本保留本地待发送内容，但没有完整离线页面包，离线时分享接收页可能暂时打不开，联网后打开 `/#capture=pending` 继续发送。

分享接收在读取表单前拒绝跨源 `Origin`，以及 `Sec-Fetch-Site: cross-site` 或 `same-site`，防止外部网页借设备登录态写入记忆。同源请求继续处理；系统或浏览器直接发起的请求可没有 `Origin`，不会仅因缺少请求头被拒绝。`Origin: null` 只在 `Sec-Fetch-Site: none` 时接受；缺少来源标记的 opaque Origin 会被拒绝。依据 [Fetch Metadata §4.3](https://www.w3.org/TR/fetch-metadata/#directly-user-initiated)，原生分享与网页发起请求的来源标记不同。Android 真机 Web Share Target 的实际请求头和安装入口仍待设备验收。

## iPhone 快捷指令

Safari 添加到主屏幕不会提供本项目的系统分享接收。可配置一个私有快捷指令，直接调用相同服务端入口。Apple 的获取 URL 内容动作支持 POST 与表单请求体。

首次配置设备钥匙：

1. 在已登录的服务器网页进入设置 · 设备，生成一次性配对码。从配对链接 `https://你的服务器/pair#code=...` 的 `code` 取得该码，不能重复使用已被网页消费的配对码。
2. 新建临时快捷指令，添加 URL，填 `https://你的服务器/api/v2/devices/exchange`。
3. 添加获取 URL 内容，方法 POST，请求体选 JSON，添加 `code` 文本为一次性配对码，`name` 文本为 iPhone 快捷指令。
4. 从返回字典取 `key`。将它配置在下述私有快捷指令的 Authorization 请求头中，不写入 URL、分享正文或待上传资料。删除临时配置指令中的配对码。设备钥匙等同这台设备的访问权限，快捷指令不得公开分享；不用时在设置 · 设备撤销。

日常文字和链接分享指令：

1. 新建快捷指令存入记忆，在详细信息中打开在共享表单中显示，输入类型选文本和 URL。
2. 添加从输入获取文本，输入设为快捷指令输入，保留完整分享文案。
3. 添加生成 UUID，保存为提交编号。本次请求失败重试时继续使用这一个编号。
4. 添加 URL，值为 `https://你的服务器/api/v2/workbench/share`。
5. 添加获取 URL 内容，方法 POST，添加请求头 `Authorization: Bearer 设备钥匙` 与 `Idempotency-Key: 提交编号`；请求体选表单，添加文本字段 `project_id` 为 `default`，`text` 为第 2 步文本。
6. 从返回字典依次取 `results` 的第一项、`project_id`、`thread_id` 和 `turn.id`。打开 URL `https://你的服务器/#view=workbench&project_id=项目编号&thread_id=线程编号&turn_id=轮次编号`，查看原有回执。

多图或视频可另建附件版指令：共享输入类型选图像、媒体、文件，POST 表单增加文件字段 `files`，值选快捷指令输入；多个图片用同名 `files` 文件字段重复传入。只传附件时 `text` 留空；同时传小红书链接和截图时，`text` 填链接文案，`files` 填截图。iOS 版本的快捷指令若不能将多项输入作为同名 multipart 文件字段发送，先用 Safari 工作台 ＋ 选择多图；不要循环拆分小红书链接与截图，避免变成多份原件。真机多项表单行为尚待验收。

请求失败后在同一次指令运行中重复获取 URL 内容动作，沿用原 UUID 和原输入。指令已退出时先查工作台再重新分享，当前文档不提供 iOS 离线队列。

## 接收接口

`POST /api/v2/workbench/share`，使用已有设备认证与用户空间隔离。`Idempotency-Key` 必需，为 1–80 位字母数字、下划线或连字符且首字符为字母数字。表单字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| project_id | 文本 | 默认 default，沿用工作台项目规则 |
| text / title / url | 文本 | 共享文案，合计最多 60000 字符；网址自动抽取 |
| files | 文件，可重复 | 最多 16 个；沿用原文件类型和大小限制 |

返回 `{ "results": [ { "project_id": "...", "thread_id": "...", "turn": { "id": "...", "receipt": { "remember": {} } } } ] }`。表示原件和轮次已持久化，整理仍可处于 processing，完成状态通过既有工作台回执读取。相同编号重发返回第一次的回执，不新增原件；编号冲突返回 409。`share_turn_interrupted` 表示执行已经失败或中断，`share_upload_interrupted` 表示附件上传状态需核对，两者都先查看工作台，核对是否已有原件，再决定是否重新分享，不自动换编号重传。未配对或设备失效沿用原 401。Cookie 导出、明确 Authorization/Cookie 凭据文本不作为普通分享接收，平台登录态只走设置中的专用入口。认识仍需用户确认才生效。

实现参考：[Chrome Web Share Target](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target)、[Apple 获取 URL 内容](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios)。核验日期 2026-10-12。
