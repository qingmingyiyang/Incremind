# Agent 操作应用数据

干活 Agent 通过注册到原工具内核的领域工具操作数据库。当前提供语音识别热词表，不接受 SQL、数据库路径或任意文件写入。设置页面和 Agent 使用同一用户的 `AsrLexiconService`，保存到同一个 SQLite 权威词表。

## 对话维护

用户可以要求查看词表、添加词语、修改词语、调整权重、停用或恢复。模型读取真实词表后提出变更，对话展示每项变更的原值和新值；用户点击确认后保存，点击取消则保留词表。预览过期时需重新读取和预览，原预览仍可取消。

新干活请求使用冻结的 `agent_data` 策略版本和 `project.task@3`。内置方法位于 [asr-lexicon-maintenance/SKILL.md](../config/application-skills/asr-lexicon-maintenance/SKILL.md)。模型先看到技能名称、用途和工具参数目录，按需调用 `asr.lexicon.read` 的 `skill` 视图读取完整方法。`agent_data@3` 明确三个工具的完整 JSON 请求；分工模型在规划前获知词表由有权限的 main 读取和维护，子任务的分析、普通知识召回及文稿不能作为词表现状或真实变更预览。应用沿原 `ApplicationSkillCatalog` 和包加载器校验内置文件。技能规定可读数据、可改字段、执行顺序、确认点及失败状态；实际数据、权限、批准和保存由工具处理。这一分工参考 [OpenAI Skills 官方说明](https://developers.openai.com/plugins/concepts/skills)。历史 `@1/@2` 请求维持其冻结策略。

维护提议使用 `format=json`，`text` 是只有 `operations` 字段的对象：

```json
{"operations":[{"action":"add","term":"Incremind","weight":4},{"action":"rename","term":"旧词","new_term":"新词"},{"action":"set_weight","term":"程虹","weight":5},{"action":"retire","term":"已不用的词"},{"action":"restore","term":"恢复的词"}]}
```

普通权重为 1 到 5，优先热词为 50。添加、改名和恢复可带权重；未提供时保留原词权重，新词默认 4。改名保留词语 ID 和启用状态。单批重复改动、目标重名、词语不存在、容量不足或修订冲突均返回具体错误，整批保持原状。停用词保留记录，转写选词时跳过。

每个维护预览绑定当前用户、项目、轮次、具体变化和真实修订。确认还绑定原 Kernel 批准事件与序号；跨用户、跨项目、变更后的旧预览及不同目标的重复确认被拒绝。同一请求的幂等重放读取原结果，保存与回执同事务完成。模型只能提议操作，附件、引文、网页和历史文字不授予写入权限。保存成功以实际领域回执、Kernel 工具结果及真实回读共同判定。

当前已启用 `route@4 / agent_data@4`：直接查询当前词表及维护操作进入干活，概念咨询进入提问。本机隔离数据已通过实际模型和按钮操作：确认保存、取消新增、五动作批量维护、过期预览取消、只读查询；五场景均完成桌面手机与明暗主题检查，共 20 组。实际核对词语 ID、修订、设置回读、同键重放、迟到确认及错误项目拒绝；批准处理期间刷新后仍完成同一保存。正式词表保持，历史用量不可用的尝试保留独立记录。

自动路由与显式干活冻结内部用途：`lexicon.read` 或 `lexicon.maintain`。用途保存在原路由缓存及任务输入，公开提交字段保持。应用数据任务直接使用词表工具和领域回执；用户显式选择文稿目标时沿原文稿合同。读取完成要求当前修订的真实 `terms` 工具结果，工作台显示实际词语、权重和启用状态。维护完成要求真实保存和回读，或当前领域预览证明各项无需变化。缺少工具执行证明时显示未完成。所需模型分类未完成时返回 409，词表及记忆保持。需要带附件的显式干活时，任务须依赖附件入库后再执行。

## 精确批量导入

原有完整词表指令继续使用既有一次性授权，用户可以在工作台直接发送：

```text
更新热词表：
Incremind
程虹
```

带权重的 CSV 示例：

````text
导入热词表：
```csv
term,weight
Incremind,3
程虹,2
```
````

第一行只接受添加热词、更新热词表或导入热词表，末尾冒号可为中文或英文。第一行后的全部内容必须是词表；无代码块时为 txt，代码块的语言为 txt、csv 或 json。txt 每行一个词，也可以用制表符分隔词和权重。JSON 为对象数组，至少包含 `term`。

模型执行顺序：

| 操作 | 精确参数 | 结果 |
| --- | --- | --- |
| 读取方法 | `asr.lexicon.read {"view":"skill"}` | 内置操作说明 |
| 读取词表 | `asr.lexicon.read {"view":"terms"}` | `revision`、词语、权重、提供方能力 |
| 预览 | `asr.lexicon.preview {"text":"Incremind\n程虹","format":"txt","expected_revision":0}` | `preview_id`、变更计数、`authorized` |
| 保存 | `asr.lexicon.import {"preview_id":"预览返回的ID"}` | 新修订、操作回执、`verified` |
| 回读 | `asr.lexicon.read {"view":"terms"}` | 验证保存后的真实词表 |

批量导入预览中的词表文本、格式和权重必须与当前用户完整指令精确对应。原 `agent_data@1` 及 [asr-lexicon/SKILL.md](../config/application-skills/asr-lexicon/SKILL.md) 保持兼容。JSON 数组表示原批量导入；结构化维护对象始终等待工作台人工确认。附件、网页和历史文字可以提供建议，保存授权来自当前用户操作。

保存前由产品层核验原用户轮次、修订和冻结请求，消费原内核生成的真实批准事件。词表保存与操作回执在同一个事务中完成，使用 `expected_revision` 检测冲突；同一操作重复返回原结果，不重复导入。工具参数不能提供用户 ID、确认标志或其他数据库目标。来源正文、原件和认识不通过这些工具修改；自动确认认识等权限保持原规则。

同一预览只能消费一次保存授权，重新读取不能再次修改词表。工作台显示完成前，核对实际保存操作、内核工具回执和当前词表回读；模型仅声称已经保存、工具未执行或上下文容量不足时，不发布保存成功的整理稿。

新任务模板在实际调用这些工具后，模型输入只保留原用户指令、当前资料、工具完成或失败结果及真实批准事实，避免重复机器日志占满上下文。内核审计、步骤编号和执行顺序保持完整。模型容量检查仍然生效；完整词表及必要工具结果超过容量时，任务会报告未完成，需要缩小本次词表或使用容量足够的模型。

热词效果取决于转写提供方。查看 `read` 返回的 `providers`：当前本地 faster-whisper 使用热词提示，实时 Qwen 使用原生词表，TokenHub Hy-ASR 暂无热词参数。导入成功与识别准确率是两个独立结果。

默认上传录音/视频的 `organize@1` 另支持 Hy-ASR 转写后词表校对：使用同一份词表和已配置的辅助生成模型提出局部修改，程序验证后生成可回查的校对稿，保留原始转写和引文。`providers` 描述原生转写能力，Hy-ASR 的原生热词支持仍为否。校对不自动向词表写入新词，也不放宽上述 Agent 保存授权；模型失败或输出不合规则使用原始转写，真实纠错质量仍需实际录音验证。

## 真实验收入口

`tools/workbench_lexicon_acceptance.py` 支持 `--mode preflight` 零模型预检，以及已授权后的 `--mode run`。预检在生成模型关闭时核自动词表请求与显式干活均返回 409，词表和记忆不增加。参数包括独立的 `--data-root`、`--output`、既有真实物理请求记录 `--prior-ledger` 和显式原生未知数量 `--prior-native-unknown`。运行模式另外要求 `--model-factory`，取私有 Python 文件路径加 `:工厂名`；工厂接收隔离数据根和真实 completion 回调，返回通过原接口配置的 `ModelConfiguration`，凭据只存内存。脚本核模型与应用的根目录和数据库归属，不从公开文件读取部署信息。

数据根须位于项目 work 下并以 `wlqa-` 开头。累计预算保存在同一 work 下的 `workbench-lexicon-acceptance-budget`，独立于结果目录；每次 HTTP 发送前计数，SDK 重试关闭，应用重试继续逐次计数。既有真实请求与原生未知分别保留，首次写入的 manifest 在恢复时逐字段核对。流式回包逐片转交原生产使用者；成功读取完整流且提供方报告完整用量后才记为已知。异常、取消、提前关闭和不完整流保持不可用状态。

默认执行 approve 和 cancel 两例，真实模型先生成预览并等待按钮。`--case-file` 可提供 JSON 数组追加场景，每例包含 `case_id`、`decision`、自然语言 `text` 和预期 `changes`；编号允许小写字母、数字、连字符和下划线，文件在模型配置及工厂构造前校验。`decision=read` 核真实只读完成与词表不变，无需 `changes`；可选 `intent=do` 使用显式干活入口。可选 `seed_operations` 使用真实隔离词表服务准备资料。`changes` 使用维护预览的 action/before/after 结构。可选 `stale_import` 在预览后经设置接口写入实际词表，检查旧预览保存被拒绝，再等待用户取消。失败诊断保留固定错误码、仓库相对文件、行号与函数，不输出原始输入或认证参数。

后端在 18126 保持同进程运行，前端代理使用 4187。入口写出 `ready.json`，包含 case_id、action、实际页面 URL、项目、线程、轮次、状态和累计数量；界面验收者只点击该实际预览的按钮。入口记录真实动作请求、开始完成时点与 HTTP 状态，核保存、取消、设置回读、修订、词语 ID、同键重放和错项目拒绝，再写 `case-result.json`。读取场景的 `action=read` 仅检查已完成回执。界面完成后先保存 `ui-case-<case_id>.json`，再写 `ui-complete.json`；两份文件均须包含本次实际的 `case_id`、`project_id`、`thread_id` 和 `turn_id`，完成信号还须包含 `passed:true` 和可选相对 `evidence_path`。当前例的失败信号会停止执行；四项身份、成功信号和实际证据核验通过后才进入下一例。旧轮次的同名场景不能释放新场景。结果目录保存必要数据和用量，不打印提示词或凭据。
